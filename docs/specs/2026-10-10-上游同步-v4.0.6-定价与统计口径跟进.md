## 设计要点

### 1. 定价同步（206 → 222）
- 新增 16 条：Claude Sonnet 5.5 / Haiku 5.5 / Opus 5.5（上游 PR #7600）、GPT-6 Sol / 6.1 Sol / Luna、GPT-5.6 Cyber、gpt-5.5 / 5.4 / 5.2-pro、gpt-4o / 4o-mini、MiMo V2.6 三档、Step 5 Preview；修正 mimo-v2.5 输出 0.29 → 0.28、o3-mini 0.55 / 2.20 → 1.10 / 4.40。对账脚本逐条比对上游 6 元组：222 = 222。
- Sonnet 5.5（$2 / $10，缓存读 0.05x = $0.10）与 Haiku 5.5（≤10 万 token 档 $0.10 / $0.50 / $0.01 / $0.125）对照官方定价页核过并用例钉住。Haiku 5.5 按提示词长度分档，>10 万档（$0.50 / $2.50）本表无档位列，与上游一样不建模。
- 「库里正成本优先、内置表只补 `total_cost_usd <= 0` 的行」契约不变。

### 2. Provider / Model 表 Tokens = 真实消耗（对齐上游 bc4d1a50 / v4.0.3）
- 两张表原先只加 `fresh_input + output`，Hero 却按 `tokensProcessed`（新增输入 + 输出 + 缓存写入 + 缓存命中）算；缓存命中率高时，表里各行加起来只是顶部总数的零头。上游 v4.0.3 把它当 bug 修了。
- SQL 侧 `realTotalTokens = (fresh_input) + output + cache_creation + cache_read`，`fresh_input` 仍按 schema 选 v13 / legacy 表达式（Codex 等 input 含缓存的行先扣再加，不会算两遍）。overlay 侧两个 overlay 的 `input` 本就是新增输入，四项直接相加。
- Tabs 只读明细表、不合并 rollups 的既有取舍不变（见 `UsageStore+Tabs` 顶部注释），所以区间跨到 rollups 时各行之和仍可能小于 Hero，这是原有偏差，不在本轮范围。

### 3. Codex 额度优先取主桶
- 一个会话里 token_count 事件会交替带不同的 `rate_limits.limit_id`：`codex` 是主额度，刷新额度时还会用 `codex_bengalfox`、`codex_spark` 等模型专属桶把同一份 token 信息再报一遍（上游 #5854 的发现）。旧实现只取最后一条，可能把模型专属桶的百分比当成 Codex 主额度显示。
- 规则：从新往旧优先取主桶（`limit_id == "codex"`，或旧版没有该字段）；同一文件里比更新的模型专属桶优先，跨文件也优先（过了 `resets_at` 的窗口在 `CodexQuota` 归零，旧快照不会误导）；所有文件都没有主桶时退回最新文件的最后一条，即改前行为，不会比改前更差。
- `tails` 是惰性序列，命中主桶就不再读后面的文件。

### 4. 额度告警线：用量 ≥90% → 剩余不到 20%
- 对齐上游 v4.0.6（0be33a84）`WARN_BELOW_PERCENT = 20`（`quotaRules.ts` / `tray.rs`，改前 10）。边界与上游用例 `toneForLeft(20) == "normal"` 一致：剩余恰好 20%（用量 80%）不告警，严格低于才告警。
- 抽成 `Shared/QuotaWarning` 的原因：边界语义只有在测试里钉住才不会被改漂，留在 `Sources/App` 测不到。

### 5. embed
- `APP_FILTER_ICON` 是从上游 `UsageDashboard` fork 的，上游后来补了 `mcode: "minimax"`，我们漏了：MiniMax Code 筛选按钮退化成灰底首字母。
- 根因是构建链只转译不查类型（esbuild），`Record<AppType, string>` 缺键不报错。`build-embed.sh` 构建前加 `tsc --noEmit -p tsconfig.json`（上游 tsconfig 覆盖 `src/**/*`，含拷进去的桥接文件，整仓约 7s）；旧代码在这一步当场报 `TS2741: Property 'mcode' is missing`。
- `keepPreviousData`：对齐上游 v4.0.0 在 summary、summary-by-app、trends、provider-stats、model-stats、logs 六类 hook 上加的 `placeholderData`，换筛选 / 时间范围 / 翻页时指标不再闪成「…」。钉子版本没有这个改动，又不能改上游文件（钉子校验只放行桥接文件），故在 `usage-embed.tsx` 里按 key 前缀 `setQueryDefaults`。detail / pricing / limits 与上游一样不挂。`CC_SWITCH_REF` 不变（仍是 `fdbe3a85`）。
