## 变更背景

- 上游 11-20 发 **v4.0.37**、11-21 发 **v4.0.38**。用户选「按推荐做」：下面 A（额度）+ B1–4（上游），并进还没发布的 v2.6.0。

## 已冻结的契约（沿用）

## A. 令牌过期：让 Claude Code 自己刷新（移植上游 `1d9b448e` 与 `claude_account/usage.rs`）
### 前人意图
- 11-18 那轮把上游 v4.0.29 的「过期登录刷新」列为「核过不跟」：当时默认用户常开终端版 Claude Code，令牌总是新的，过期时保留上次的数就够了。用户改用 Desktop 之后这个前提不成立。
- `ClaudeCredential` 不解析 `expiresAt`，过没过期由接口的 401/403 裁决（与上游一致）——保留。
### 改法
1. `ClaudeQuotaFetch.run`：直接查询得到 `.expired` 时，在默认的 `~/.claude` 里跑一次 `claude -p /usage`（同一进程内 10 分钟最多一次，失败也算），再读 `~/.claude.json` 的 `cachedUsageUtilization`：`accountUuid` 等于同一文件里 `oauthAccount.accountUuid`、`fetchedAtMs` 在 10 分 45 秒以内，就用其中的 `utilization`（同构，`ClaudeQuotaParser.parse` 直接解析）作为这次的额度。令牌刷新以后，下一次直接查询也就恢复了。
2. **被拒令牌的指纹**（本应用新增）：得到 `.expired` 时记下这个令牌 SHA-256 的前 16 位十六进制（落盘到 UserDefaults，不存令牌本身）；之后读到的还是同一个令牌，就不再发这个注定失败的请求，直接走第 1 步；令牌一换（指纹不同）立刻恢复直接查询。
3. **怎么起 `claude`**：
   - 位置依次找 `~/.local/bin/claude`、`~/.claude/local/claude`、`/opt/homebrew/bin/claude`、`/usr/local/bin/claude`，都没有再在登录 shell 里问一次（zsh 用 `whence -p`，避开用户给 `claude` 起的 alias；其它用 `type -P`；15 秒）。找不到就不跑，额度保持「—」，日志写明原因。
   - 环境从白名单起：`HOME`、`USER`、`LOGNAME`、`SHELL`、`TMPDIR`、`LANG` / `LC_*`、代理变量（`http(s)_proxy`、`all_proxy`、`no_proxy` 大小写两种），`PATH` 固定为 `/usr/bin:/bin:/usr/sbin:/sbin`；再加上游的四个开关 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`、`DISABLE_TELEMETRY=1`、`DISABLE_ERROR_REPORTING=1`、`DISABLE_AUTOUPDATER=1`。上游是按名单删（`ANTHROPIC_*`、`CLAUDE_CODE_USE_*`、令牌类），我们从白名单起：CC Usage 若是在某个 Claude Code 会话里被启动的，宿主的 `ANTHROPIC_BASE_URL`、会话令牌之类一个也带不进去（11-22 实测宿主会话里就有 `ANTHROPIC_BASE_URL`）。
   - 参数照搬上游：`-p /usage --output-format json --tools "" --strict-mcp-config --setting-sources "" --no-session-persistence`；工作目录 `HOME`；标准输入输出全接 /dev/null；45 秒没结束就杀掉。
4. 日志：刷新后读到缓存记 info；读不到记原因（找不到 claude、超时、缓存不存在 / 太旧 / 不是这个账号的）。
### 模块设计
- `Shared/Quota/ClaudeUsageCache`（纯）：`.claude.json` 的内容 → 当前登录账号的缓存额度（取数时刻 + 各档额度）；`isFresh(now:)`（10 分 45 秒）。
- `Shared/Quota/ClaudeUsageCLI`：参数、环境白名单、候选位置（纯）；`run(...)` 经 `ProcessRunner`（加环境与工作目录两个参数）。
- `Shared/Quota/TokenFingerprint`（纯）。
- `App/QuotaService`：`ClaudeLoginRecovery`（actor：被拒指纹 + CLI 节流，指纹落盘）；`ClaudeQuotaFetch.run` 接线（读凭据 → 指纹 → 直接查询或跳过 → `.expired` 时 CLI 刷新 + 读缓存）；`ClaudeConfigReader.profilePath()` 供套餐名与缓存共用。
- 依赖方向：`App → Shared/Quota → ProcessRunner`，无环。

### 和上面规格的出入
- 登录 shell 里找 claude：zsh 用 `whence -p`、bash 用 `type -P`（上游一律 `command -v`）。用户常给 claude 起 alias（加默认参数），这时 `command -v claude` 打出的是 alias 的定义、拿不到路径——本机实测就是这样。
- 子进程的 PATH 不并登录 shell 的 PATH（上游并）：claude 所在目录 + Homebrew + 系统目录。node 装在别处的 npm 安装会跑不起来，日志里有退出码。
- 一次只跑一个：正在跑时后来者等同一次（上游让同一账号的后来者直接读缓存）。实际调用都经 QuotaCache 的在途去重，不会并发。
- `ClaudeQuotaFetch.recovery` 不给默认值（测试必须注入假的，免得真去跑 claude）；读配置、起进程这些阻塞的活放 GCD 线程。
- v4.0.38 前端多用了一个文案键 `usage.detail.noTimingSession`；语言包瘦身只去掉 en.json 以外的包，不受影响。
