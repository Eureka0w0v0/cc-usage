# [TECHNICAL SPECIFICATION] 菜单栏弹窗趋势图改成主窗口 v4 趋势图的迷你版

## 背景与根因
- 用户反馈弹窗里的趋势图看不懂。对照代码，问题有四个：
  1. 80pt 高的小图同时叠了 6 层：Cache Hit 面积、4 条 token 线、换算到 tokens 轴上画的成本虚线。没用量的小时都是 0，6 层压在底边，成了一条红绿相间的虚线；
  2. 弹窗关了坐标轴（`showAxes: false`），看不出几点、多少量；
  3. 只有最近一小时有量时，峰值贴在最右边，曲线从上一小时的 0 斜着冲上去；
  4. 样式还停在主窗口 v3（五线、双纵轴）。主窗口 v4（上游 `UsageTrendChart.tsx`，v4.0.22）已改成单指标、单色、柱形或面积、`<YAxis tickCount={3}>`、只有横向网格，两边不一致。
- 前人意图：五线双纵轴是对齐 v3 主窗口时的设计；`NiceScale` 照抄 recharts 让两边轴顶一致；`CrosshairLayer` 单独一层，悬停时图表不重绘。v4 主窗口不再画五线，对齐的目标跟着变了；「照抄 recharts 取整」和「悬停不重绘」两条继续保留。

## 设计（11-02 用户选方案 A：做成主窗口 v4 的迷你版，跟随主窗口设置）
- **跟随主窗口**：指标取 UserDefaults `embed.usage.trendMetric`（主窗口指标条，上游 localStorage `cc-switch.usage.trendMetric` 的原生镜像；没选过或认不出 → tokens），样式取 `embed.usageDisplay` 的 `trendChartType`（没设置或认不出 → 柱形，同上游 resolveTrendChartType）。弹窗用 `@AppStorage` 绑定这两个键，主窗口一改立即跟上。
- **指标取值**（`TrendMetric`，同上游 buildUsageTrendChartData）：tokens = 输入 + 输出 + 缓存写 + 缓存读；命中率 = 缓存读 ÷（输入 + 缓存写 + 缓存读），分母为 0 记 nil。
- **纵轴**（`TrendYAxis` + `NiceScale`，同 recharts combineNiceTicks 的两个分支）：
  - tokens / 花费 / 请求数：定义域 [0, 'auto'] → `niceTicks(dataMax:tickCount: 3)`（getNiceTickValues），轴顶扩到最后一个刻度；
  - 命中率：定义域 [hitRateAxisFloor, 1] → `fixedDomainTicks`（getTickValuesFixedDomain），刻度不出界，末段可能不等长；
  - Decimal 换回 Double 经十进制字符串，与 decimal.js 的 toNumber 一样取最近的 Double（`NSDecimalNumber.doubleValue` 会差一个 ulp）。
- **几何**（`TrendLayout`，纯函数）：柱形 band 刻度取格中心、面积 point 刻度首尾贴边（单点居中）；柱宽 = 格宽 80%（barCategoryGap 10%）、封顶 36；圆角 [3, 3, 0, 0] 不超过柱高和半个柱宽；横轴标签逐条移植 getTicksEnd（preserveEnd，minTickGap 12）；悬停柱形按所在格、面积按最近的点；面积按缺值断段；曲线逐条移植 d3 curveMonotoneX。
- **文字**（`TrendFormat`）：tokens / 请求数刻度 = Intl compact（en-US，最多 1 位小数，halfExpand，进位到 1000 换下一档）；金额刻度 = formatMoneyTick（加千分位，`Fmt.costAxis` 随之改）；命中率刻度一位小数、去掉末尾 .0；悬停数值 = fmtInt / money(v, 4) / formatHitRatePercent；横轴写 HH:mm。
- **视图**（`TrendChart`）：图画在 Equatable 的 Canvas 里，悬停时不重绘；悬停指示画在图下面（柱形整格底色、面积虚线竖线），图上面画 activeDot（r 4、白描边 2）和一行提示「14:00 ■ Tokens 123,456」，右边放不下翻到左边。配色取主窗口 `.dark` 设计 token（--chart-usage #38BDF8、--chart-grid #2C2C31、--text-3 #9A9AA2、--bg-subtle #26262A）。
- **弹窗**：图上方一行标题「<指标> · hourly」（同主窗口 titleMetric），图高 104pt，开悬停。Widget（扩展未注册）用同一张图，固定 Tokens / 柱形，五线图例换成同样的标题。
- **删除**（确认已无其他引用）：五线图、六行提示框、五色图例 `ChartLegend`、`PlotFrameKey`、`CrosshairLayer`、`TrendChart.axisMaxes`、`NiceScale.axisMax` / `tickCount`、`Fmt.tokensAxis`、`Fmt.cost6`、`Theme.cost`。
- **已知差异**：金额刻度小于 1e-6 时 JS 写成 5e-7、这里写 0.0000005（刻度来自十进制步长，正常数据碰不到）；面积图孤立的单个点不画（与上游 connectNulls = false、dot = false 一致）。

## 爆炸半径
- `TrendChart` 的调用方：`App/MenuBarPanel`（弹窗）、`Widget/WidgetViews`（中、大尺寸）。
- `NiceScale` 只剩 `TrendYAxis` 一个调用方；`Fmt.costAxis` 只被走势图刻度用。
- 不动数据层（`UsageStore+Trend` 的小时桶不变），不动 embed（主窗口照旧是上游前端）。

## 测试
- 期望值一律取自主窗口实际打包的 recharts 3.5.1 / d3-shape 3.2.0 / Intl（cc-switch 目录下用 node 跑出），命中率下限另从上游源码里把函数抽出来原样执行：
  - `NiceScaleTests`：3 档刻度 24 组、5 档轴顶 31 组、固定定义域 11 组、全 0 与非法输入；
  - `TrendAxisTests`：指标 / 样式的默认值与解析、各指标取值、纵轴、hitRateAxisFloor（上游单测 8 组 + 补 2 组）、刻度与悬停文案、HH:mm；
  - `TrendLayoutTests`：band / point 位置、柱宽封顶、圆角夹紧、纵向映射、横轴标签 8 组（字宽打桩成字符数 × 6 喂给 recharts getTicks）、悬停取格、断段、单调曲线 7 组；
  - `TrendChartRenderTests`：空、单桶、全 0、命中率全空 / 断段、尖峰 × 柱形 / 面积 × 有无坐标轴离屏渲染不崩；像素断言尖峰柱子画在最后一格、颜色是 #38BDF8、0 值格子没有颜色。
- 变异测试 25 个（含套餐 5 个）全部被杀。首轮存活 2 个——命中率余量「至少 2 个百分点」、单调斜率的半割线上限——上游自带的用例和最初选的曲线点都分不出，补了 0.968 / 0.969 与「直线」「单调上凸」两组后被杀。
- 真机：弹窗面积 / 柱形随主窗口下拉切换，纵轴与主窗口相同，悬停提示在右边放不下时翻到左边；`/Applications` 装的是 Release 构建。
