# [TECHNICAL SPECIFICATION] 菜单栏小窗口走势图纵轴取整对齐主窗口

## 现象
菜单栏弹窗的迷你走势图与主窗口走势图：每条曲线的形状一致，但紫线（缓存读）与红虚线（花费）谁高谁低正好相反。

## 根因
- **数据同源**：弹窗 `snapshot().trend` 与主窗口桥接 `get_usage_trends` → `trendBuckets` 都走 `UsageStore.trend()`；真库逐桶比对一致。
- **两图都是双纵轴**：tokens 与花费各自取整定轴顶，但取整规则不同——
  - 弹窗 `TrendChart.niceCeil`：只取 1 / 2 / 2.5 / 3 / 4 / 5 / 6 / 8 / 10 × 10ⁿ；
  - 主窗口 Recharts YAxis（默认 tickCount 5、domain `[0, auto]`）：`getNiceTickValues`，粗步长 = max / 4，按 0.05×10ⁿ 向上取整（粗步长首位在个位数量级时按 0.1×10ⁿ），轴顶 = 4 × 步长。
- 例：峰值 10.5M / $4.9 → 弹窗 20M / $5（紫 53%、红 98%），主窗口 12M / $8（紫 88%、红 61%）。双轴图里两条线的相对高度本无数值含义，但两图规则不同就会互相矛盾。

## 改动
- 新增 `Sources/Shared/NiceScale.swift`：逐行移植 recharts 3.5.1 `getNiceTickValues([0, max], 5, true)`。用 Decimal 精确运算（对应 decimal.js-light）；全 0 → 4（对齐 `getTickOfSingleValue(0)`）；`min = 0` 时修正因子分支不会触发，已在注释中说明。
- `TrendChart`：新增可测的静态 `axisMaxes(_:)`，两轴都用 NiceScale；轴顶每次渲染只算一次；Y 轴抽成 `yAxis(_:factor:)`；删除 `niceCeil`。
- `Fmt.costAxis`：$ 刻度文本对齐 Recharts `$${value}`（按需显示小数、不加千分位）。原 `Int(rounded)` 会把 1.25 / 2.5 标成 $1 / $3，花费不足 $1 时整排显示 $0。只有 Widget 大尺寸视图（带坐标轴）看得到。

## 爆炸半径
- `TrendChart` 调用方：`MenuBarPanel`（弹窗，不显示坐标轴）、`WidgetViews` 两处（Widget，当前未注册）。主窗口走 embed，不受影响。
- 数据层零改动。

## 测试
- `TrendChartScaleTests`（3 例）：示例数据轴顶 = 12M / $8；四条 token 线逐条做最大值；全 0 → 4 / 4。
- `NiceScaleTests`（3 例）：31 组 Recharts 金标准（在 cc-switch 目录用 node 调主窗口打包的 recharts 生成），覆盖粗步长恰为 10ⁿ、恰在边界 / 刚越界、小数；全 0；非法输入给出有限轴顶。
- `FormattingTests.testCostAxis`。
- 先红后绿：旧实现下用例给出 20M / $5 与全 0 时 1 / 0.0001。
- 变异验证：档位条件写反 / 两档都用 0.1 / digitCount 差一位 / ceil 写成四舍五入 / 全 0 返回 1 / 两轴数据源互换 / tokens 轴只看 hit / $ 标签退回取整 / 带千分位，9 个变异体全部被杀。
- 离屏渲染（`ImageRenderer`，真库数据）对比：改前红虚线高于紫线，改后与主窗口同序。
- 全量 144 测试通过。
