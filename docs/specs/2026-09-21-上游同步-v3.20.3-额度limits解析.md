## 设计要点

### 解析规则（对齐上游 `parse_claude_quota`）
三段来源，后者覆盖前者：
1. **已知顶层窗口**：按 `knownTiers` 顺序读，`utilization` 缺失 / `null` / 非数字即跳过该窗口。
2. **未知顶层窗口**：API 新加的窗口类型保留原名；`extra_usage` / `limits` / `spend` / `member_dashboard_available` 不是窗口。
3. **`limits[]` 模型专属周限额**：
   - 只收 `kind == "weekly_scoped"` **且** `group == "weekly"`；
   - `scope.surface` 存在且非 null → **跳过**（某个使用场景的子限额不能并进整个模型的周额度，否则显示成偏高的假值）；
   - `scope.model.display_name` trim + 小写后映射 `fable/opus/sonnet` → `seven_day_fable/_opus/_sonnet`，其余跳过；
   - `percent` 必须存在、有限且 ≥ 0；同一 tier 重复出现时**首条胜出**；
   - 覆盖同名旧窗口，不追加第二份；
   - **不按 `is_active` 过滤**——`0%` 与 `resets_at: null` 都是有效额度，不存在的额度接口直接省略。

任何一条畸形只跳过它自己，不影响其余窗口。

### 顺带修掉的隐性缺陷
旧实现直接遍历 `[String: Any]` 产出数组，**顺序跟着字典哈希走**。菜单栏按名查所以无感，但 embed 面板拿的是数组 → 每次刷新码片可能跳位。现按 `knownTiers` 稳定排序，未知窗口统一排最后并保持相互次序。

### 定价
`db 优先` 契约不变：`model_pricing` 查得到就用库里的，内置表只对 `total_cost_usd <= 0` 的行现场补算。本轮同步时本机库中零成本行数为 **0**，故调价对现有数字零影响，属修补潜在偏差（一旦出现上游未收录的新模型走兜底，旧 sonnet-5 价会高估 50%）。
