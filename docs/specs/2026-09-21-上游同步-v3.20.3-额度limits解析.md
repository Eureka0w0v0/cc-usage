## 设计要点

### 解析规则（对齐上游 `parse_claude_quota`）
三段来源，后者覆盖前者：
1. **已知顶层窗口**：按 `knownTiers` 顺序读，`utilization` 缺失 / `null` / 非数字即跳过该窗口。
2. **未知顶层窗口**：API 新加的窗口类型保留原名；`extra_usage` / `limits` / `spend` / `member_dashboard_available` 不是窗口。
3. **`limits[]` 模型专属周限额**：
   - 只收 `kind == "weekly_scoped"` **且** `group == "weekly"`；
   - `scope.surface` 存在且非 null → **跳过**（某个使用场景的子限额不能并进整个模型的周额度，否则显示成偏高的假值）；
   - `scope.model.display_name` trim + 小写后映射 `fable/opus/sonnet` → `seven_day_fable/_opus/_sonnet`，其余跳过；
   - `percent` 必须存在、有限且 ≥ 0；同一 tier 重复出现时**首条胜出**；
   - 覆盖同名旧窗口，不追加第二份；
   - **不按 `is_active` 过滤**——`0%` 与 `resets_at: null` 都是有效额度，不存在的额度接口直接省略。

任何一条畸形只跳过它自己，不影响其余窗口。

### 顺带修掉的隐性缺陷
旧实现直接遍历 `[String: Any]` 产出数组，**顺序跟着字典哈希走**。菜单栏按名查所以无感，但 embed 面板拿的是数组 → 每次刷新码片可能跳位。现按 `knownTiers` 稳定排序，未知窗口统一排最后并保持相互次序。

### 定价
`db 优先` 契约不变：`model_pricing` 查得到就用库里的，内置表只对 `total_cost_usd <= 0` 的行现场补算。本轮同步时本机库中零成本行数为 **0**，故调价对现有数字零影响，属修补潜在偏差（一旦出现上游未收录的新模型走兜底，旧 sonnet-5 价会高估 50%）。

## 额度徽标渲染（同轮补齐）
解析层修好后三档一度无人消费——菜单栏只暴露 `5H`/`7D` 两个码片，embed 的 `QuotaBadges` 同样写死只取这两个（cc-switch 带 `seven_day_fable` label 的 `SubscriptionQuotaFooter.tsx` 属主应用外壳，不在 embed 入口内）。本轮把 embed 侧接上：

- `QUOTA_BADGES` 清单按 `knownTiers` 同序列出五档，显式列一遍而非依赖后端数组顺序。
- **`always` 语义**：`5H` / `Week` 是所有套餐都有的窗口，无数据时也占位显示 `—`（否则首屏 `tiers` 还空着时工具栏会先塌再弹）；`Fable` / `Opus` / `Sonnet` 走 `limits[]`，接口只在账号真有该额度时才返回，故**按需出现**——没订到 Fable 的账号不该看见一排 `—`。
- 浏览器预览验证（shim 给 fable 12% / opus 47.5%、故意不给 sonnet）：DOM 实测四个徽标 `5H · 42% · resets in 1h59m · max`、`Week · 78%`、`Fable · 12%`、`Opus · 48%`，**Sonnet 不渲染** → 两条分支都走到了。
- 菜单栏维持 `5H`/`7D` 两档不变（寸土寸金，且要过宽度 governor）。

## 用量 app 全集补齐（同轮补齐）
排查 `mcode` 时发现漏的不止一个：上游 `KNOWN_APP_TYPES`（`src/types/usage.ts`）是 7 项，本项目 `MBApp` 只有 5 项对得上——**`pi` 和 `mcode` 都缺**。`pi` 在 v3.20 就进了 `providerNameSQL`（`_pi_session`），但 `MBApp` 始终没加，即按 AI 分组的码片里根本没有 Pi 这一栏。

| 补的东西 | 位置 |
|---|---|
| `MBApp` 追加 `pi` / `mcode` | `MenuBarKeys.swift`；追加一律放末尾，`allCases` 的顺序就是菜单栏各段排列 |
| `MBKey.groupPi` / `groupMcode` | 同上 |
| 设置面板两个新分组 | `MenuBarSettingsView.swift`，Quota 行按实际情况占位 `No quota API` |
| `_mcode_session` → `MiniMax Code (Session)` | `UsageSQL.providerNameSQL`（**真 bug**：不补则 Provider Stats 直接露出裸 `_mcode_session`） |
| `brand-minimax.png` | 由上游 `src/icons/extracted/minimax.svg` 经 AppKit 渲染 + alpha 通道重组为 64×64 纯黑模板图 |

设计决定：
- **不收 `openclaw` / `hermes`**——上游注释明确说它们「only appear as managed apps」，不产生用量行。
- **不收 `claude-desktop`**——查询层就折叠进 `claude`（`foldedAppL/R`），单列只会显示半个数。
- **`iconAsset` 由 `String` 改为 `String?`**，`pi` 诚实地返回 `nil`。上游对 Pi 同样没有图标（`ProviderIcon icon="pi" showFallback={false}`）；两个调用点的 `icon` 参数本来就是 Optional，改动零摩擦——比指向一个不存在的文件名、靠 `NSImage(named:)` 返回 nil 兜底要诚实。
- 两处 `MBApp.allCases` 的消费点（`MenuBarLabel.pieces` / `PanelModel` 的码片查询）都是「没勾就 `continue`」，加 app **不带来任何额外 SQL 或渲染**。

### 防再漏机制：`scripts/check-app-types.sh`
`pi` 漏一轮、`mcode` 漏到下一轮，根因是**两边没有任何机制互相提醒**。新增只读对拍脚本，比对上游每加一种 harness 必动的三处真理源：

1. `KNOWN_APP_TYPES`（`src/types/usage.ts`）↔ `MBApp` 的 case 列表，本仓库独有项走 `LOCAL_ONLY` 白名单（当前只有 `antigravity`）；
2. `provider_name_coalesce`（`usage_stats.rs`）的占位 `provider_id` → 可读名 ↔ `UsageSQL.providerNameSQL`，缺失与**拼写不一致**都报（后者会让 `providerName` 筛选对不上）；
3. `CACHE_INCLUSIVE_APP_TYPES`（`sql_helpers.rs`）↔ `UsageSQL.cacheInclusiveApps`，这条直接改变 fresh input 口径。

**变异验证 5/5**：删 `MBApp.mcode`、删 `_mcode_session` 映射、把 `Pi (Session)` 拼错、往 `cacheInclusiveApps` 混入 `mcode`、往 `MBApp` 塞上游没有的 `hermes`——五种改坏全部被脚本抓出，还原后复绿。
