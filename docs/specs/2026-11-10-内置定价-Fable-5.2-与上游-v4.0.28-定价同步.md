# [TECHNICAL SPECIFICATION] 内置定价补 Claude Fable 5.2 + 上游 v4.0.28 定价同步

## 变更背景
- 2026-11-10 起会话日志里出现 `claude-fable-5-2`（Claude Fable 5.2）；cc-switch seed（v4.0.28 / main `bd487e83`）、其 DB `model_pricing`、本项目内置表均无此行 → 入库与面板都记 $0。
- 候选链不会把末尾的 `-2` 当日期尾剥成 `claude-fable-5`（只剥 8 位 / 6 位 / ISO 日期），前缀兜底又是 `id-` 单向 → 查不到。是漏价，不是错价。
- 官方定价（platform.claude.com/docs/en/about-claude/pricing，2026-11-10 核对）：$8 / $40，5 分钟缓存写 $10，**缓存读 $0.20（0.025x）**——不是常规 0.1x 的 $0.80，也不是 Fable 5.1 的 $0.25；照抄 fable-5-1 行则四项全部高 25%。Claude Mythos 5.2 同价。1M 上下文无溢价；1 小时缓存写 $16、fast mode $16 / $80、batch $4 / $20 本表无列。
- 上游 v4.0.22 → v4.0.28 的定价 seed 有 4 条新增未同步：`258c367f`（v4.0.23：grok-4.6-build / grok-4.7-build / grok-4.7-build-fast，此前已放在本地先行区）、`f0252817`（v4.0.25：gpt-6.1-terra）。原有 232 条零改动。

## 受影响模块

## 设计要点
- 沿用本地先行区：上游优先合并；上游收录 `claude-fable-5-2` 后 `testLocalExtrasAreAbsentUpstream` 报红，届时删本地行。
- 只同步定价 seed，不动面板钉子（`CC_SWITCH_REF` 仍为 v4.0.22 的 `b7642674`）、不重建 embed。v4.0.23 – v4.0.28 其余与用量相关的改动（Codex 请求模型别名去重 #7643、汇率自动获取 #8716、定价表搜索 #9205 等）不在本轮范围。
- 查价链路不变：DB 已有价始终优先；内置表只对 DB 无价或成本 ≤ 0 的行生效。
- 1 小时缓存写不另加列：叠加层按 `ClaudeCacheWriteBilling` 的 ×1.6 现算，$10 × 1.6 = $16，与官方 1 小时档一致。
- 已知缺口（与上游一致，本轮不动）：fast mode 的 2 倍价（Fable 5.2 为 $16 / $80）。上游的 Claude 会话导入与本项目叠加层都不读 `usage.speed`，fast 档请求按标准价计。

## 测试
- 内置表命中 fable-5-2 / mythos-5-2 四个价 + `[1m]` / 命名空间变体；与 fable-5 的 input 不相等（`-2` 不被当日期尾剥掉）。
