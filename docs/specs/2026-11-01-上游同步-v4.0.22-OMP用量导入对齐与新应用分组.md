## 1. OMP 用量：对齐上游导入器（#9046），单独成组

### 根因
- v4.0.22 起上游自己导入 `~/.omp/agent/sessions`（`session_usage_omp.rs` + Pi 引擎 `session_usage_pi.rs`），行身份是 `omp_session:<sha256>`，app_type `omp`。
- OmpOverlay 的 request_id 是 `session:msg_…` / `omp:…`，`pruneRowsAlreadyInDB` 只查 `session:` 前缀 → 上游入库的行一条也剔不掉。用户把 cc-switch 升到 4.0.22 后，OMP 全部历史会算两遍（上游首次导入就是全量）。

### 前人意图（切斯特顿栅栏）
- 按模型家族把 OMP 拆进 claude / grokbuild / gemini / codex：当时 OMP 的 anthropic 走订阅 OAuth，消耗的是 Claude 订阅额度，要和 5H / Week 徽标对得上。10-16 起 OMP 改用 Console 个人 key 按量计费，这个前提已不成立；上游也把 OMP 当独立应用。
- 不查 model_pricing：怕把 OMP 自带的正确成本抹成 0。上游只在自报成本为 0 时才查价，不会抹掉自带成本，所以照上游改不违背这个意图。
- 采用 OMP 的 ttft 当首字：当时上游没有 OMP 导入，没有口径可对。现在上游的 OMP 行首字恒为 NULL。

### 改法（逐条照 v4.0.22 `parse_pi_file` / `parse_usage_record` / `pi_request_identity` / `insert_pi_record`）
- **文件发现**（`pi::session_files_for(&omp::OMP)`）：根目录 = cc-switch `settings.json` 的 `ompConfigDir`（`~` 展开）+ `/sessions`，否则 `~/.omp/agent/sessions`；顶层只收「根/项目目录/*.jsonl」（深度 2、普通文件、不跟符号链接）；每个会话文件同名去扩展名的目录下递归收子会话（跳过 `subagent-artifacts`）；排序。和 Pi 共用同一个根时只留首行是 `{"type":"title"}` 的文件。`PI_CODING_AGENT_SESSION_DIR` 等环境变量不看：cc-switch 和本应用都是 GUI 进程，拿不到 shell 环境，两边结果一致。
- **整文件规则**：超过 128 MiB 不导入；首个有效 JSON 必须是 session header（OMP 允许前面有 title 行），header 的 id 要符合 tree id 规则，否则整个文件不导入；超过 500000 条 entry 整文件报错；末行不完整就停在那里、下一轮再读。
- **逐条规则**：
  - 计入的种类：assistant 消息、带 usage 的 toolResult、compaction、branch_summary、model_usage。前两者以外只有 assistant 和 model_usage 算「有归属」。
  - 四维 tokens 全为 0、自报成本也为 0，并且不是失败请求 → 跳过。失败请求（stopReason 为 error / aborted）即使 0 用量也记一条：aborted 记 499，error 记 500，错误信息截到 4096 字符，没有信息时用 `Oh My Pi request aborted/failed`。
  - 有归属：provider_id = `provider`（截到 512 字节），没有时用 `_omp_session`；model = `responseModel`，没有时用 `model`，再没有就记 `unknown`。没有归属：`_omp_session` / `unknown`。
  - created_at：先取顶层 timestamp，再取消息里的 timestamp，再取 header 的，最后用文件 mtime。整数在 ±1e11 以内按秒算，否则按毫秒。
  - 成本：自报 total > 0 时用自报值（total 为 0 就用四项之和）；否则按库里的 model_pricing 现场算（omp 不属于「输入含缓存」的应用，缓存写入不拆 1 小时档）；库里也查不到时回落内置表，和查询层给零成本行补价的口径相同。
  - 耗时：`duration` 四舍五入后落在合理区间才用；否则用消息 timestamp 到顶层 timestamp 的差值估算。首字恒为空。
  - 子会话：OMP 没有截止时间，嵌套文件照常计入；toolResult 投影只有在它指向的所有子会话文件都在本轮文件里时才跳过。
- **行身份**：request_id = `omp_session:` + sha256（`omp-session-request-v3` / 种类 / entry id / 顶层 timestamp 的 JSON）；没有 entry id 时用 semantic_id = `omp_session_semantic:` + sha256（种类、两个时间戳、消息的 9 个字段、content 或 summary、usage 的规范化 JSON）。每个字段带 8 字节大端长度前缀；JSON 按类型编码，对象键按 UTF-8 字节排序，数字按 serde_json 的输出格式（整数原样，浮点用 ryu 的最短表示和小数点规则）。
- **跨文件去重**：照上游账本的逻辑在内存里去重（按文件排序后先到先得）：request_id 见过就跳过；有 entry id 的只和没有 entry id 的旧行比 semantic_id，没有 entry id 的和所有行比。
- **入库剔除**：pending 行的 request_id 出现在 `proxy_request_logs`，或出现在 `session_usage_dedup`（data_source = `omp_session`；明细 30 天后被汇总删掉，只剩这本账）里 → 剔除；semantic 规则同上。缺表（旧库）就只查前者。
- **归属与展示名**：app_type 恒为 `omp`，data_source 恒为 `omp_session`。展示名照 `provider_name_coalesce`：先查 providers 表 (id, `omp`) 的 name，`_omp_session` 显示 `Oh My Pi (Session)`，其余显示 provider_id 原文。
- **OverlayRow** 新增 `statusCode`（默认 200）、`errorMessage`、`requestModel`；UsageStore 里凡是把叠加行「全部算成功」的地方（汇总、供应商 / 模型统计的成功率、请求日志的状态码筛选、请求详情）改按行自带的状态码算。SessionOverlay 的行都是 200，行为不变。
- **查价表抽成共享**：SessionOverlay 里的 model_pricing 快照与 `findPricing`（候选精确 → 前缀 → 内置表）原样搬进 `Shared/PricingTable.swift`，两个叠加层共用。SessionOverlay 行为不变（冻结库对拍要逐字一致）。

### 用户可见的变化（发版说明要写）

## 测试设计（先红后绿）
- 解析：照搬上游 OMP 测试的 4 行样例（assistant、model_usage、aborted 0 用量、compaction 占位）→ 4 行、状态码与成本对；子会话早于首次同步也计入（600）；共用 Pi 根时只留 title 行开头的文件；无 header / header 无 id / 首行不是 session → 整文件跳过；不完整末行留到下一轮。
- 身份：用上游 Rust 代码算出的 request_id / semantic_id 当金标准（含浮点、科学计数、嵌套对象、unicode 键）；ryu 格式化单测。
- 去重：同一 entry 出现在两个文件只算一次；库里 proxy_request_logs 或 session_usage_dedup 有这个 id → 剔除；旧库没有 session_usage_dedup 不报错。
- 归属：app_type 恒 omp；展示名按 providers 表 → 占位名 → 原文。
- 汇总：499 / 500 行计入请求数但不计入成功；状态码筛选能筛出失败的叠加行；请求详情带错误信息。
- 查价：自报为 0 时按库价算；库里没有时回落内置表；自报 > 0 时不查价。
- 发现规则：深度 2、子目录递归、跳过 subagent-artifacts、不跟符号链接、`ompConfigDir` 覆盖。
- 名称映射、MBApp 覆盖面靠 `check-app-types.sh`。
